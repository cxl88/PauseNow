# 华为真机技术验证报告（停一下 PauseNow）

> 文档版本：v1.0
> 最后更新：2026-07-18
> 验证设备：华为 Mate 40 Pro（NOH-AL10）
> 系统版本：HarmonyOS 4.2 / EMUI 14.2（Android 12 / API 31）
> 应用版本：0.1.0（applicationId `com.pausenow.app`）
> 构建基线：Kotlin 2.3.20，AGP 9.0.1，JDK 17，compileSdk/targetSdk 36，minSdk 26，Jetpack Compose BOM 2024.09.00

## 1. 概述与结论

本报告沉淀停一下（PauseNow）在华为 Mate 40 Pro（HarmonyOS 4.2）真机上阶段 3 闭环复测的过程与结果。验证目的是确认 Stage 1 时华为后台无障碍事件 0% 冻结的问题，在 Stage 2/3 改用 FGS + UsageStats 轮询后是否被绕开，以及闭环全链路在华为后台管控下是否可靠。

**核心结论**：

- **前台时**：FGS + UsageStats 轮询稳定工作，每 3 秒命中抖音前台，闭环全链路（open -> grant -> expired -> extend -> end）全部验证通过。
- **后台可靠性（关键发现）**：华为后台管控**比 OPPO 更严**。
  - **未开"启动管理"时**：PauseNow 退后台约 20-30 秒后，**进程被华为直接杀掉（连 FGS 常驻通知都保不住）**，检测循环停止。服务连接标记 `DEAD`。
  - **开启"启动管理"手动放行后**（自启动 + 关联启动 + 后台活动）：退后台后进程持续存活，FGS 每 10 秒被系统跟踪（`BTopFgs`），检测循环继续命中抖音。**UsageStats 路线成功绕开华为后台冻结。**
- **Stage 1 的华为后台 0% 冻结问题已解决**：前提是用户必须在华为"启动管理"里手动放行停一下的后台运行。
- **权限显式降级验证通过**：撤销 Usage Access 后检测循环记 `degraded=usageAccessDenied` 并跳过干预；恢复后检测恢复。
- **隐私不变量保持**：`canRetrieveWindowContent=false`、仅包名三字段、无 `INTERNET`/`QUERY_ALL_PACKAGES`/`SYSTEM_ALERT_WINDOW`。

**部署门槛（华为特有）**：用户必须手动在"设置 -> 电池 -> 启动管理"里把停一下改为手动管理并勾选三项（自启动 + 关联启动 + 后台活动），否则后台检测失效。这是华为特有的引导项，需在 Onboarding 或文档中明确提示。

## 3. 验证过程与结果

### 3.1 授权与 FGS 启动（成功）

- **Usage Access**：Stage 1 已授予，`appops get GET_USAGE_STATS = allow`，复用。
- **无障碍服务**：手动在系统设置开启"停一下"服务，`enabled_accessibility_services` 含 `com.pausenow.app/.accessibility.PauseAccessibilityService`，`accessibility_enabled=1`。
- **FGS**：`dumpsys activity services` 确认 `isForeground=true`，foregroundId=1001，常驻通知 channel=`pausenow_foreground`。

### 3.2 前台检测与闭环全链路（成功）

检测循环日志（前台时，每 3 秒）：
```
PauseNow.Detection: foreground=com.ss.android.ugc.aweme matchedRule=rule_1784369197852
PauseNow.Detection: decision=Allow passExpired=false
```

闭环干预事件记录（`pausenow_intervention_events`，按时间从旧到新）：
```
open -> grant -> expired -> extend -> expired -> extend -> expired -> extend -> expired -> end
```

| 事件 | 含义 | 结果 |
|---|---|---|
| open | 打开抖音触发打开前干预 | ✅ |
| grant | 点"放行"授予 5 分钟通行 | ✅ |
| expired | 通行到期，下次打开抖音弹出到期干预 | ✅（多次） |
| extend | 点"延长 3 分钟"（extensionCount 累加） | ✅（多次） |
| end | 点"结束并回桌面"，通行清空，回桌面 | ✅ |

结束操作后：
- `passes` 清空（`{}`）
- 前台回到 `com.huawei.android.launcher`（桌面）
- 检测循环继续运行

### 3.3 后台可靠性（核心，分两阶段）

#### 3.3.1 未开"启动管理"——进程被杀（失败 -> 暴露华为特有门槛）

过程：打开抖音、确认检测循环正常后，按 Home 退到桌面（PauseNow 与抖音均退后台），等待约 20-30 秒。

结果：
- `ps -A | grep pausenow` 无匹配——**进程不存在**。
- `dumpsys activity processes` 显示 `ConnectionRecord{... DEAD com.pausenow.app/.accessibility.PauseAccessibilityService}`——服务连接标记 DEAD。
- 检测循环日志停止。
- 华为 SWAP_AK 的 `appLruQueue` 仍列出 `com.pausenow.app`，但进程已被回收。

结论：华为后台管控直接杀进程，连 FGS 常驻通知都无法保活。这比 OPPO（进程存活但无障碍事件节流）更激进。

#### 3.3.2 开启"启动管理"后——进程保活，检测继续（成功）

操作：在华为"设置 -> 电池 -> 启动管理"找到"停一下"，改为手动管理，勾选**自启动 + 关联启动 + 后台活动**。重新打开停一下 app（进程被杀后需重启）。

结果（退后台后日志）：
```
18:29:15  BG com.pausenow.app                                  ← 退后台
18:29:15  抖音 visible:true                                     ← 抖音变前台
18:29:20  ProcessStats: BTopFgs ... com.pausenow.app proc state 3   ← FGS 被系统跟踪
18:29:35  ProcessStats: BTopFgs ... com.pausenow.app proc state 3   ← 每10秒一条，存活
18:29:45  ProcessStats: BTopFgs ... com.pausenow.app proc state 3
18:29:48  PauseNow.Detection: foreground=aweme decision=Allow      ← 检测循环继续命中
18:29:55  ProcessStats: BTopFgs ... com.pausenow.app proc state 3
```

结论：开启启动管理后，华为不再杀进程，FGS 持续存活，检测循环继续命中抖音。**UsageStats 轮询成功绕开华为后台冻结**，Stage 1 的 0% 冻结问题在 Stage 2/3 架构下解决（需用户放行后台）。

### 3.4 权限显式降级（成功，验证阶段 3 收尾修复）

用 `adb shell appops set com.pausenow.app GET_USAGE_STATS ignore` 模拟撤销 Usage Access：

```
18:36:36  PauseNow.Detection: degraded=usageAccessDenied    ← 正确降级，跳过干预
18:36:39  PauseNow.Detection: degraded=usageAccessDenied
```

恢复 `GET_USAGE_STATS allow` 后：
```
18:37:00  PauseNow.Detection: foreground=com.huawei.android.launcher matchedRule=null   ← 检测恢复
```

结论：阶段 3 收尾修复的显式权限降级在华为上工作正常。Usage Access 关闭时不再 hardcode `permissionsReady=true`，而是记 `degraded` 日志并跳过干预。

### 3.5 inFlight 互斥锁泄漏修复（成功，华为复测暴露并验证）

**问题暴露**：华为复测中出现"打开抖音不拦截、通行过期 5 分钟无反应"。排查发现检测循环判定正确（`decision=RequireExpiredIntervention`），但 `InterventionLauncher` 日志为 `launchSuppressed (cooldown or in-flight)`--干预被防重复机制抑制。

**根因**：`InterventionState.inFlight` 是无超时 set，依赖 `InterventionActivity.onDestroy` 调 `release` 清除。华为上 Activity 退到后台/被回收时 `onDestroy` 延迟或不调用，`release` 缺失，`inFlight` 残留，导致同一包干预被永久抑制。

**修复**：
- `InterventionState.inFlight` 改为带时间戳 map，超过 5 分钟（`STALE_MS`）视为泄漏自动清除，记 `inFlightStaleCleared` 日志（兜底自愈）。
- `InterventionActivity` 的 `onGrant/onExtend/onEnd` 回调里**主动调 `InterventionState.release`**，用户点按钮立即释放，不等 `onDestroy`（华为上更可靠）。
- 新增 `InterventionStateTest` 5 用例覆盖互斥/冷却/泄漏自愈。

**验证**：修复后真机连续触发 `expired -> extend -> expired -> extend -> ...`，`extensionCount` 累计到 4-5 次，每次 `expired` 干预都能 `launched`（不再 `suppressed`）。证明 inFlight 不再卡死、回调 release 正常工作。

```
20:13:44  Intervention: launched packageName=com.ss.android.ugc.aweme   ← 不再 suppressed
事件序列: ... expired -> extend -> expired -> extend -> expired (extensionCount=4+)
```

结论：华为上 Activity 生命周期异常导致的 inFlight 泄漏已修复并验证。修复前同类问题会表现为"干预弹一次后再也不弹"。

## 6. 已知限制与风险

| 限制/风险 | 现状 | 处理 |
|---|---|---|
| 华为必须手动开"启动管理" | 不开则后台进程被杀 | Onboarding / 文档明确引导；考虑检测到未放行时提示 |
| 单设备验证 | 仅华为 Mate 40 Pro 一台 | 可补华为其他机型或小米 |
| 长时后台稳定性 | 本次仅测分钟级 | 留待阶段 4 做 8 小时待机观察 |
| P95 干预延迟未实测 | 无埋点 | 阶段 4 补埋点 |
| 华为 adb 启动 systemmanager activity 被拦 | `am start -n ...StartupNormalAppListActivity` 报 HwActivityManagerService 异常 | 启动管理页需用户手动进入；`am start -a huawei.intent.action.HSM_STARTUPAPP_MANAGER` 可跳转 |
| 锁屏/切后台长时 | 未专测 | 阶段 4 |
| 抖音 cold start splash 短暂盖干预页 | adb 冷启抖音时 splash 动画几秒内盖住 InterventionActivity，之后干预页浮上来可操作 | 非阻断；Stage 4 可优化启动时序/优先级 |
| force-stop 会禁用无障碍 | `adb force-stop com.pausenow.app` 后华为把停一下从 enabled_accessibility_services 移除，约 1 分钟系统自动重绑 | 测试时避免 force-stop；用重装或等待重绑 |

## 7. 华为复测指引

### 7.1 安装与授权

```powershell
adb install -r app\build\outputs\apk\debug\app-debug.apk
# 启动 app，Onboarding 引导开 Usage Access + 无障碍
adb shell am start -n com.pausenow.app/.MainActivity
```

### 7.2 开启启动管理（华为必须）

设置 -> 电池 -> 启动管理 -> 停一下 -> 关闭自动管理 -> 勾选**自启动 + 关联启动 + 后台活动**。

或 adb 跳转：
```
adb shell am start -a huawei.intent.action.HSM_STARTUPAPP_MANAGER
```

### 7.3 闭环验证

1. 建规则：Home -> 保护规则 -> 新建 -> 选抖音 -> 通行 1 分钟 -> 保存。
2. 打开抖音 -> 弹打开前干预 -> 放行。
3. 等 1 分钟 -> 再开抖音 -> 弹到期干预 -> 延长或结束。
4. Home -> 今日报告 -> 核对 open/grant/expired/extend/end 计数。

### 7.4 后台可靠性验证

```powershell
adb logcat -c
# 打开抖音确认检测循环命中，按 Home 退后台，等 1-2 分钟
adb logcat -d -s PauseNow.Detection
adb shell ps -A | findstr pausenow   # 进程应仍存活
```

退后台后 `ProcessStats: BTopFgs ... com.pausenow.app proc state 3` 持续出现 = FGS 保活成功。

### 7.5 权限降级验证

```powershell
adb shell appops set com.pausenow.app GET_USAGE_STATS ignore
adb logcat -d -s PauseNow.Detection   # 应见 degraded=usageAccessDenied
adb shell appops set com.pausenow.app GET_USAGE_STATS allow
adb logcat -d -s PauseNow.Detection   # 应恢复 foreground=
```
