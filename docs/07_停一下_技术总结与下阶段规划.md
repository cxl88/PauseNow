# 停一下 PauseNow - 阶段 1-3 技术总结与下阶段规划

> 文档版本：v1.0
> 最后更新：2026-07-18
> 当前阶段：Stage 3（Alpha 产品化）功能完成，待收尾验证
> 适用范围：阶段 1-3 已交付功能的总结、华为/OPPO 流程梳理、阶段 4+ 的 UI 与功能铺垫

## 1. 文档目的

本文档沉淀停一下（PauseNow）阶段 1-3 的技术成果，服务于两个目标：
1. **为下一阶段（Stage 4 UI 设计与功能完善）做铺垫**：梳理技术债、待改进项、已验证的边界条件，让下一阶段的设计与开发有据可依。
2. **描述已完成功能与已解决问题**：让新加入的同学快速理解当前系统能做什么、踩过哪些坑。
3. **梳理华为与 OPPO 两台真机的功能流程**：国产 ROM 适配是本项目核心难点，两条流程的差异与共同点是下阶段多设备推广的基准。

## 2. 项目背景与当前阶段

PauseNow 是面向 Android 的短视频使用干预产品：用户打开目标应用（如抖音）时弹出干预页，限时放行，到期再提醒。本地优先，无账号、无服务端、不上传。纯 Kotlin 原生（Jetpack Compose UI + Kotlin 控制引擎，单进程）。

阶段进展：
- **Stage 1**（权限与前台事件 Spike）：证明授权后能获得前台包名事件；暴露国产 ROM 后台无障碍事件冻结风险。
- **Stage 2**（干预与通行 Spike）：pivot 到 FGS + UsageStats 轮询主检测；完成干预/通行/到期闭环。
- **Stage 3**（Alpha 产品化，当前）：Onboarding、应用列表、多规则、本地持久化、今日报告、数据清除、诊断、签名 release APK；华为/OPPO 真机闭环验证；修复 inFlight 泄漏、干预页被盖等真机问题。

构建基线：Kotlin 2.3.20，AGP 9.0.1，JDK 17，compileSdk/targetSdk 36，minSdk 26，Jetpack Compose BOM 2024.09.00，applicationId `com.pausenow.app`。

## 3. 已完成功能

### 3.1 权限与授权
- Usage Access 状态检测与系统设置跳转（`AndroidPermissionGateway.hasUsageAccess` / `openUsageAccessSettings`）。
- AccessibilityService 状态检测与跳转（`isAccessibilityServiceEnabled` / `openAccessibilitySettings`）。
- 无障碍醒目披露门槛：用户勾选"已读已理解"才能开无障碍（`SpikeViewModel.disclosureAccepted`）。
- 运行时通知权限（Android 13+ `POST_NOTIFICATIONS`，`MainActivity`）。
- 显式权限降级：Usage Access 关闭时检测循环记 `degraded=usageAccessDenied` 并跳过干预（`PauseAccessibilityService.detectOnce`）。
- 华为机型特有引导：启动管理三项 + 后台弹出界面权限（`AndroidPermissionGateway.isHuawei` / `openStartupManager` / `openAppDetails`）。

### 3.2 检测层（双输入）
**主检测（Stage 2/3）**--前台服务内 UsageStats 轮询，绕开国产 ROM 后台无障碍冻结：
- `PauseAccessibilityService` 在 `onServiceConnected` 提升为前台服务（`FOREGROUND_SERVICE_TYPE_SPECIAL_USE` + 常驻通知）。
- `Handler` 每 `DETECTION_INTERVAL_MS=3000ms` 跑 `detectOnce()`：读快照 -> 显式权限降级检查 -> `queryCurrentForeground` -> `RuleEngine.evaluate` -> `InterventionLauncher`。
- `queryCurrentForeground` 用 `UsageStatsManager.queryUsageStats`（60 秒窗口）取 `lastTimeUsed` 最大的包。**用 `lastTimeUsed` 而非 `MOVE_TO_FOREGROUND`**：用户停留超几秒后事件窗口查不到当前应用，`lastTimeUsed` 始终可靠。

**辅助输入**--无障碍事件，前台可见时实时流（后台被冻结，仅补充）：
- `TYPE_WINDOW_STATE_CHANGED` 过滤 -> `EventDebouncer` 去抖 -> `PackageExclusionPolicy` 排除 -> `ForegroundEventStore` 持久化（最近 50 条）-> `ForegroundEventBus` 推送 UI。

### 3.3 规则引擎（纯逻辑）
- `rule/RuleEngine.kt`：纯逻辑 `object`，输入 `EvaluationInput`，输出 `Decision`（`Degraded`/`Ignore`/`Allow`/`RequireOpenIntervention`/`RequireExpiredIntervention`）。
- 优先级：权限失效 -> Degraded；排除包 -> Ignore；非目标 -> Allow；有效通行 -> Allow；通行到期 -> RequireExpiredIntervention；默认 -> RequireOpenIntervention。多规则按 `priority` 取最高。
- `ProtectionRule`：`id`/`name`/`targetPackages`/`passDurationMs`/`extensionSeconds`/`enabled`/`priority`。
- 单元测试 `RuleEngineTest` 覆盖各决策分支与优先级。

### 3.4 通行管理
- `pass/PassManager` + `pass/PassStore`：grant/extend/end/current，`SharedPreferencesPassStore` 持久化（`packageName -> ActivePass` JSON），跨重启恢复。
- `extendPass`：已过期通行从"现在"起算延长，避免延长后仍过期。
- `ActivePass`：`ruleId`/`packageName`/`grantedAtMs`/`expiresAtMs`/`extensionCount`。
- 单元测试 `PassManagerTest`。

### 3.5 干预
- `intervention/InterventionActivity`：`MODE_OPEN`（打开前干预，"即将打开 X，是否放行 N 分钟"）/ `MODE_EXPIRED`（到期干预，"时间到，延长或结束"）。用户选择直接调 `PassManager` + `ExpiryController`，再返回目标应用或桌面。
- `intervention/InterventionLauncher`：检测循环中调用，防重复 + 启动 Activity。按 `LaunchResult`（STARTED/RECOVER/SUPPRESSED）处理：首次 record 事件，重盖不 record。
- `intervention/InterventionState`：单例防重复状态。
  - 冷却：同包上次干预 + `cooldownMs`（30s）内不重复弹。
  - 互斥：同包干预页在前台（`showing=true`）时不重复弹。
  - **被盖重盖**：干预页被目标应用盖到后台（`showing=false`）时，检测循环 `tryStart` 返回 RECOVER，重新 startActivity 盖回去，解决抖音 main 启动时序竞争盖回干预页。
  - **泄漏自愈**：inFlight 带启动时间，超 `STALE_MS`（5 分钟）视为 Activity 未正常 onDestroy，自动清除（华为 onDestroy 延迟/不调用）。
  - `onGrant/onExtend/onEnd` 回调主动 `release`，不等 onDestroy。
- 单元测试 `InterventionStateTest` 覆盖互斥/冷却/重盖/泄漏自愈。

### 3.6 到期
- `intervention/ExpiryController` + `ExpiryAlarmReceiver`：`AlarmManager` 精确闹钟（`setExactAndAllowWhileIdle`，S+ 检查 `canScheduleExactAlarms`）在 `expiresAtMs` 触发，发高优先级通知。
- 真正的到期拦截弹页由检测循环事件驱动（用户下次打开目标应用时 `RequireExpiredIntervention`），通知是"到时即提醒"兜底。

### 3.7 报告
- `report/InterventionEventStore`：记录 `open`/`expired`/`grant`/`extend`/`end` 事件（SharedPreferences， newest 500）。
- `ReportScreen`：今日统计（各事件计数）+ 按应用分组。

### 3.8 UI 与导航
- `ui/nav/PauseNowNavHost`：onboarding/home/rules/ruleEdit/appPicker/report/settings 多屏，起始路由由 `OnboardingStore.isCompleted()` 决定。
- `OnboardingScreen`：权限引导 + 华为机型后台保活与弹出引导。
- `HomeScreen`：权限状态卡 + 华为引导卡（机型命中时）+ 保护状态卡（规则数/启用数/目标包/通行信息，`RulesViewModel`）+ 入口按钮。`ON_RESUME` 重载规则。
- `RulesScreen` / `RuleEditScreen`：规则列表、新建/编辑/删除/启用，从应用列表选目标包。
- `AppPickerScreen`：`AppRepository.queryIntentActivities(MAIN+LAUNCHER)` 列可启动应用 + 搜索，无 `QUERY_ALL_PACKAGES`。
- `SettingsScreen`：清除全部数据（规则/通行/事件，不动权限和 Onboarding）+ 诊断（设备信息）。
- `SpikeScreen`：Stage 1/2 诊断面（保留）。

### 3.9 本地持久化（Native Snapshot Store）
- `snapshot/SharedPreferencesSnapshotStore`：UI 写、服务读的最小同步快照。
- `ProtectionSnapshot` schema v2：`rules: List<ProtectionRule>` + `settings: ProtectionSettings` + `updatedAt` + `schemaVersion`。读取时自动迁移 v1 `protectedPackages` 为单条规则。
- 服务不依赖 UI 存活，每 tick 读快照。

### 3.10 构建
- `assembleDebug` -> debug APK（17MB）。
- `assembleRelease` -> release APK（12MB，debug 签名，Alpha 分发；正式 keystore 待上架前生成）。
- `scripts/check-stage1-static.ps1`：8 项隐私不变量静态检查。
- `scripts/android-env-check.ps1`：本地全流程（java/adb + 测试 + lint + debug 构建）。

## 4. 已解决的关键问题

| 问题 | 根因 | 解决方案 | 验证 |
|---|---|---|---|
| 国产 ROM 后台无障碍事件冻结 | OPPO 后台节流 15%、华为后台 0% 冻结 | pivot 到 FGS + UsageStats 轮询作主检测，无障碍降为前台辅助 | OPPO/华为真机后台检测命中 |
| `MOVE_TO_FOREGROUND` 查不到当前应用 | 用户停留超几秒后窄窗口查不到 | 用 `queryUsageStats` + `lastTimeUsed`（60s 窗口） | 真机稳定命中 |
| `getLaunchIntentForPackage` 返回 null | Android 11+ 包可见性限制 | manifest 加 `<queries>` LAUNCHER 声明 | 返回目标应用 |
| inFlight 互斥锁泄漏（打开抖音不拦截、5 分钟无反应） | 华为 `InterventionActivity.onDestroy` 延迟/不调用，`release` 缺失，inFlight 永久残留 | inFlight 带时间戳，超 5 分钟自愈；回调主动 release | 华为连续 expired/extend 多次不卡死 |
| 干预页被抖音盖住（无感知） | 华为"后台弹出界面"权限禁止后台弹界面；抖音 main 时序竞争盖回 | ① 引导开"后台弹出界面"权限 ② 被盖重盖机制（showing 状态 + RECOVER） | 华为干预页稳定盖抖音 10 秒不盖回 |
| 权限关闭不降级 | `permissionsReady` hardcode true | `detectOnce` 接入 `hasUsageAccess()`，关闭记 `degraded` 跳过 | OPPO/华为降级日志确认 |
| 首页只显示单包名 | `SpikeViewModel.protectedPackage` 单字符串 | HomeScreen 增挂 `RulesViewModel`，多规则摘要 + 多包感知通行 | 首页显示规则数/启用数/目标包 |
| 华为后台杀进程（连 FGS 都保不住） | 华为"启动管理"默认禁后台 | 引导开启动管理三项 + Onboarding/Home 卡片 | 开启后进程持续存活 |
| 数据迁移 | 阶段 2 flat `protectedPackages` -> 阶段 3 多规则 | `ProtectionSnapshot.fromJson` v1->v2 自动迁移 | 单元测试覆盖 |

## 5. 华为功能流程（Mate 40 Pro / HarmonyOS 4.2）

### 5.1 首次配置流程
1. 安装 APK -> 启动 -> Onboarding。
2. 开 Usage Access（系统设置）。
3. 开无障碍服务（系统设置，含披露门槛）。
4. **华为特有①**：设置 -> 电池 -> 启动管理 -> 停一下 -> 关闭自动管理 -> 勾选自启动 + 关联启动 + 后台活动（**必须**，否则退后台 20-30 秒进程被杀）。
5. **华为特有②**：设置 -> 应用 -> 停一下 -> 权限 -> 后台弹出界面 -> 允许（**必须**，否则干预页被抖音盖住、无感知）。
6. Onboarding 完成 -> Home -> 保护规则 -> 新建 -> 从应用列表选抖音 -> 设通行时长/延长时长 -> 保存。

### 5.2 运行时干预流程
1. 用户打开抖音 -> 检测循环（FGS UsageStats 3s 轮询）查到 `foreground=com.ss.android.ugc.aweme` -> 匹配规则 -> `RuleEngine.evaluate`。
2. 无通行 -> `RequireOpenIntervention` -> `InterventionLauncher.launchOpen` -> `InterventionActivity`（MODE_OPEN）弹出，盖在抖音之上（开了后台弹出界面权限 + 被盖重盖机制保障稳定显示）。
3. 用户点"放行 N 分钟" -> `PassManager.grantPass` + `ExpiryController.scheduleExpiry` -> 返回抖音，通行有效（检测循环 `Allow`）。
4. 到期 -> `ExpiryAlarmReceiver` 发高优先级通知；用户下次打开抖音 -> 检测 `RequireExpiredIntervention` -> `InterventionActivity`（MODE_EXPIRED）弹出。
5. 用户点"延长 N 分钟"（`extendPass`，`extensionCount+1`）或"结束并回桌面"（`endPass` + `cancelExpiry` + 返回桌面）。
6. `InterventionEventStore` 记录 open/expired/grant/extend/end，`ReportScreen` 展示今日统计。

### 5.3 华为特有限制与处理
- **未开启动管理**：退后台 20-30 秒进程被杀（`ConnectionRecord DEAD`），检测循环停。-> Onboarding/Home 引导开启。
- **未开后台弹出界面**：干预页被抖音盖，无感知。-> Onboarding/Home 引导开启 + 被盖重盖。
- **force-stop 禁无障碍**：`adb force-stop` 或系统强杀后，华为把停一下从 `enabled_accessibility_services` 移除，约 1 分钟系统自动重绑。-> 测试避免 force-stop；用重装或等待重绑。
- **抖音 cold start splash 短暂盖干预页**：几秒后干预页浮上来（重盖机制保障），非阻断。

## 6. OPPO 功能流程（PJU110 / ColorOS 14）

### 6.1 首次配置流程
1. 安装 APK -> 启动 -> Onboarding。
2. 开 Usage Access + 无障碍服务。
3. OPPO 后台管控相对宽松，未强制要求启动管理（若遇后台被杀可引导自启动 + 后台锁）。
4. Onboarding 完成 -> Home -> 保护规则 -> 新建 -> 选抖音 -> 保存。

### 6.2 运行时干预流程
与华为一致（检测 -> RequireOpenIntervention -> 干预页 -> 放行 -> 到期 -> RequireExpiredIntervention -> 延长/结束）。OPPO 后台 FGS + UsageStats 可靠，干预页可正常弹出（未观察到被盖问题）。

### 6.3 OPPO 特性
- 后台无障碍事件节流 15%（进程存活），但 FGS + UsageStats 后台可靠，已绕开。
- Stage 2/3 闭环验证通过（open/grant/expired/extend/end 全事件）。

## 7. 华为 vs OPPO 对比

| 维度 | OPPO（ColorOS 14） | 华为（HarmonyOS 4.2） |
|---|---|---|
| 后台无障碍事件 | 节流 15% | 完全冻结 0% |
| 后台进程存活（未额外设置） | 存活 | **被杀**（连 FGS 保不住） |
| FGS + UsageStats 后台可靠 | 是 | **需开启动管理** |
| 干预页盖前台 app | 正常 | **需开后台弹出界面权限** + 被盖重盖 |
| 必开权限 | Usage Access + 无障碍 | Usage Access + 无障碍 + **启动管理三项** + **后台弹出界面** |
| 闭环验证 | 通过 | 通过（需上述权限） |
| force-stop 副作用 | 一般不禁无障碍 | **禁无障碍**，约 1 分钟自动重绑 |

共同点：FGS + UsageStats 轮询主检测、RuleEngine 纯逻辑、干预/通行/到期闭环、本地持久化、隐私不变量一致。

## 8. 下阶段铺垫（Stage 4 UI 设计与功能完善）

### 8.1 UI 设计方向
- **首页**：当前已支持多规则摘要，可进一步增强--保护状态可视化（各规则剩余通行时间）、权限状态一键检测与修复、空状态引导。
- **干预页**：优化视觉层级与触达（当前被盖重盖可能短暂闪烁，可加过渡动画/振动反馈）；区分 open/expired 视觉样式；支持自定义文案。
- **规则编辑**：当前仅单包单规则，UI 预留多包、时间段、每日限额的编辑入口（数据模型 `ProtectionRule` 已具备扩展字段基础）。
- **报告**：今日报告 -> 周/趋势报告，可视化图表（参考 Stage 5 规划）。
- **Onboarding**：分步引导（权限 -> 规则 -> 厂商适配），厂商检测更精细（华为启动管理/后台弹出界面状态检测，未开时强提示）。
- **设置**：诊断页增强（一键复制诊断、权限修复入口）、隐私政策入口、反馈入口。

### 8.2 功能完善方向（对应架构方案 Stage 4-5）
- **稳定性**：8 小时待机耗电观察、锁屏/切后台长时稳定性、P95 干预延迟埋点（当前无埋点）。
- **规则能力**：固定时间段规则、每日总限额、睡前模板、多规则优先级 UI、单次通行模式。
- **多设备**：小米/vivo 复测，覆盖更多国产 ROM；华为其他机型。
- **通知与拦截**：到期通知优化、权限失效通知、Boot 状态检查。
- **报告**：每周报告、使用趋势。
- **分发**：正式 keystore 签名、应用商店审核材料、隐私政策、崩溃收集最小化（封闭 Beta）。
- **厂商适配深化**：检测到 HUAWEI/HONOR 时自动引导启动管理 + 后台弹出界面；小米/vivo 自启动引导。

### 8.3 技术债
- **Gradle 弃用警告**：`android.builtInKotlin=false`、`org.jetbrains.kotlin.android` 插件弃用，AGP 10 前迁移到 built-in Kotlin。
- **UsageStats 检测延迟**：重装/启动后停一下自身 `lastTimeUsed` 干扰 60s 窗口检测；检测循环 3s 间隔有 2-3s 延迟。可探索事件驱动补充（不影响隐私不变量）。
- **抖音 cold start splash 盖页**：重盖机制已兜底，但理想方案是检测时机前置（Stage 4）。
- **`permissionsReady` 只校验 Usage Access**：无障碍靠"服务在运行即开启"结构性保证，未自检（避免国产 ROM 误判）。Stage 4 可加可靠的自检。
- **release APK 为 debug 签名**：Alpha 可用，上架前需正式 keystore。
- **README/docs 阶段标记过期**：根 `README.md` 与 `docs/README.md` 仍写"阶段 1 Spike"，需刷新。

### 8.4 隐私不变量（贯穿所有阶段，不可破坏）
- Accessibility 配置：`typeWindowStateChanged` only、`canRetrieveWindowContent="false"`、`isAccessibilityTool="false"`。
- manifest：无 `QUERY_ALL_PACKAGES`、无 `SYSTEM_ALERT_WINDOW`、无 `INTERNET`（含 debug/profile 变体）。
- 应用选择：仅 `MAIN+LAUNCHER` + `<queries>`，不扫全部安装包。
- 代码：不调 `getRootInActiveWindow()`、不读 `event.text`、不遍历节点树、不自动点击/手势、不上传。
- 检测层只产出三字段：`detectedAtMs`、`eventType`、`packageName`。
- `scripts/check-stage1-static.ps1` 8/8 必须保持通过。
